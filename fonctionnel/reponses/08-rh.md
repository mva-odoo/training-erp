## Exercice 8.1

**L'équipe de Torréfaction Sablon.**

### 1. Les départements

**Employés → Départements → Nouveau** : `Direction`, `Production`, `Vente`.
Le **manager** se choisit parmi les employés : créez donc d'abord les fiches de Sophie et Karim (étape 2), puis revenez
sur les départements pour indiquer leur manager.

> Astuce : on peut aussi créer un département **depuis la fiche employé**, en tapant son nom dans le champ *Département*.

### 2. Les employés

**Employés → Nouveau** pour chaque personne : nom, **poste** (champ libre ou *Poste* lié au recrutement), **département**,
**manager** (onglet *Travail*). Proposition :

| Employé | Département | Poste | Manager |
|---|---|---|---|
| Sophie Laurent | Direction | Gérante | — |
| Karim Benali | Vente | Responsable commerciale | Sophie |
| Lucas Peeters | Production | Magasinier | Sophie |
| Inès Dubois | Direction | Comptable (mi-temps) | Sophie |
| 2 torréfacteurs | Production | Torréfacteur | Sophie |
| 2 vendeurs | Vente | Vendeur en boutique | Karim |

Le **manager** de l'employé est rempli automatiquement avec le manager du département : vérifiez-le.

### 3. Lier aux utilisateurs

Fiche employé → onglet **Paramètres** → **Utilisateur lié** : choisissez l'utilisateur correspondant.
(Inversement, le bouton **Créer un utilisateur** en haut de la fiche crée un utilisateur à partir de l'employé.)

Pourquoi c'est indispensable : sans lien, quand Lucas se connecte, Odoo ne sait pas **quel employé** il est.
Il ne peut alors ni demander de congé, ni encoder de dépense, ni pointer.

### Vérifier l'organigramme

Fiche d'un vendeur → onglet **Travail** → l'**organigramme** à droite montre la chaîne : vendeur → Karim → Sophie.
C'est le champ **Manager** de chaque fiche qui construit cette hiérarchie.

## Exercice 8.2

**Les congés de l'équipe.**

### 1. Allocation pour tous

**Congés → Management → Allocations → Nouveau** :
- type de congé : **Congés payés** ;
- mode : **par société** (ou *par département*, *par étiquette*), plutôt que *par employé* → une allocation pour **tous** ;
- durée : **20 jours** ; période : l'année en cours ;
- **Valider** / **Approuver**.

Odoo génère une allocation par employé. Une allocation **non approuvée** ne compte pas dans le solde.

### 2. Jours fériés

**Congés → Configuration → Jours fériés → Nouveau** : `Fête nationale`, du 21/07 au 21/07 ; `Assomption`, le 15/08.

### 3. La demande de Lucas

Connecté en tant que Lucas (navigation privée) → **Congés → Mon temps → Tableau de bord** → **Nouveau** (ou cliquez sur les
dates dans le calendrier) → type **Congés payés**, du lundi au jeudi → la durée affichée est **3 jours** → **Enregistrer**.
La demande est **À approuver**.

### 4. L'approbation

Connectée en tant que Sophie → **Congés → Management → Congés** → filtre *À approuver* → la demande de Lucas → **Approuver**.
Lucas reçoit une notification.

### Pourquoi 3 jours ?

La durée d'un congé est calculée sur l'**horaire de travail** de l'employé (par défaut, du lundi au vendredi), **moins les
jours fériés**. Du lundi au jeudi = 4 jours ouvrés, moins le 15 août = 3 jours déduits du solde : 20 − 3 = **17 jours**.

## Exercice 8.3

**Recruter un vendeur.**

1. **Recrutement → Nouveau** (sur la vue des postes) : nom `Vendeur en boutique` → **Créer**. Puis **Configurer** sur la carte :
   département *Vente*, nombre de **personnes à recruter** : 1, description du poste.
   Bouton **Page d'offre** → sur le site, interrupteur **Publié**.
2. Navigation privée → `/jobs` → l'offre → **Postuler** → nom, e-mail, téléphone, CV → **Envoyer**.
   La candidature apparaît dans la colonne **Nouveau** du poste.
3. Ouvrez la candidature et faites-la avancer en cliquant sur les étapes de la barre d'état (ou en glissant la carte dans le kanban) :
   *Qualification → Premier entretien → … → Contrat signé*.
   À l'étape *Contrat signé*, le bouton **Créer un employé** apparaît → il ouvre une fiche employé pré-remplie
   (nom, e-mail, téléphone, département, poste) → **Enregistrer**.
4. Un autre candidat → bouton **Refuser** → motif (*Ne correspond pas au profil*…) → option d'envoyer un e-mail de refus
   au candidat → **Refuser**. La candidature est archivée, mais gardée (utile s'il repostule).

> Chaque étape peut envoyer un **e-mail automatique** au candidat (« Votre candidature a bien été reçue », « Invitation à
> un entretien »). On les configure dans **Recrutement → Configuration → Postes → Étapes**.

## Exercice 8.4

**Un déjeuner client.**

### 1. Karim encode la dépense

Connecté en tant que Karim → **Dépenses → Mes dépenses → Nouveau** :
- description `Déjeuner avec le gérant du restaurant X` ;
- catégorie : **Repas** (ou *Restaurant*) ;
- total : `54` ; **Payé par : Employé (à rembourser)** ;
- **Joindre le reçu** : la photo du ticket ;
- **Soumettre**.

> Sur mobile, on peut photographier le ticket directement. 🔒 La lecture automatique du ticket (montant, date) est un service payant.

### 2. L'approbation

Par défaut, c'est le **manager de l'employé** qui approuve. Karim est le manager du département Vente, mais **son** manager à lui est **Sophie** : c'est elle qui approuve. (Personne n'approuve ses propres dépenses.)
Connectée en tant que Sophie → **Dépenses → Mes dépenses → Dépenses à traiter** → la dépense de Karim → **Approuver**.

### 3. Comptabiliser et rembourser

Connectée en tant qu'Inès → la dépense approuvée → **Comptabiliser** (Odoo crée l'écriture : une dette envers Karim) →
**Payer** → journal Banque → **Créer un paiement**. La dépense passe à **Payé**.

| Étape | Qui | Pourquoi |
|---|---|---|
| Soumettre | L'employé | Il déclare la dépense et fournit le justificatif |
| Approuver | Le manager | Il valide que la dépense est justifiée pour l'entreprise |
| Comptabiliser / payer | La comptabilité | Elle enregistre la dette et rembourse |

Trois personnes différentes : c'est la **séparation des tâches**, un principe de contrôle interne.

## Exercice 8.5

**Les présences.**

1. **Présences → Mode kiosque** : l'écran du kiosque s'ouvre (à mettre en plein écran sur une tablette).
   **Identifier manuellement** → choisissez un employé → (code PIN s'il est configuré) → **Arrivée**.
   Recommencez plus tard → **Départ**.
2. **Présences → Gestion** (ou **Analyse → Présences**) : une ligne par pointage, avec les **heures travaillées**.
   Regroupez par employé et par jour pour voir le total.

> Pour pointer avec un **badge**, renseignez son identifiant dans la fiche employé (onglet **Paramètres** → *ID du badge*)
> et utilisez un lecteur de badges ou la caméra de la tablette.

## Enquête

**« Je n'ai droit à rien ! »**

| Cause | Vérification |
|---|---|
| L'allocation de l'exercice 8.2 a été faite **avant** son arrivée : elle a créé une allocation pour chaque employé **existant** à ce moment-là | **Congés → Management → Allocations**, filtre sur l'employé |
| Une allocation existe mais n'est **pas approuvée** | Statut de l'allocation |
| L'employé n'est **pas lié à son utilisateur** : Odoo affiche les soldes de… personne | Fiche employé → onglet **Paramètres** → *Utilisateur lié* |
| La période de l'allocation ne couvre pas la date demandée | Dates de validité de l'allocation |

La première cause est la plus fréquente. Solution : une **allocation individuelle**, au **prorata** de sa date d'arrivée.

> Pour éviter le problème à l'avenir : les **plans de cumul** (*Congés → Configuration → Plans de cumul de congés*) attribuent
> automatiquement des jours chaque mois (par exemple 1,67 jour par mois), y compris aux nouveaux arrivants.

## Exercice 8.6

**L'arrivée d'un nouveau torréfacteur.**

| # | Étape | Application |
|---|---|---|
| 1 | (Si recruté via Odoo) Candidature → **Contrat signé** → **Créer un employé** | Recrutement |
| 2 | Compléter la fiche : département **Production**, poste, **manager Sophie**, horaire de travail, date d'entrée | Employés |
| 3 | Créer son **utilisateur** (bouton *Créer un utilisateur*) avec des droits minimaux, et vérifier le lien | Employés / Paramètres |
| 4 | Badge ou **code PIN** pour le kiosque (onglet **Paramètres** de l'employé) | Employés |
| 5 | **Allocation** de congés payés au prorata : arrivée au 1er juillet → 6 mois sur 12 → **10 jours** | Congés |
| 6 | Vérifier qu'une dépense test est bien proposée à Sophie pour approbation | Dépenses |

L'**ordre** compte : sans fiche employé (2), pas d'allocation (5) ; sans utilisateur lié (3), pas de demande de congé
ni de dépense ; sans manager (2), personne n'approuve.

> Odoo propose aussi des **plans d'onboarding** (*Employés → Configuration → Employé → Onboarding / Offboarding*) :
> une liste d'activités assignées automatiquement aux bonnes personnes à l'arrivée d'un employé
> (« préparer le poste », « créer l'accès », « remettre le badge »…). C'est la version « automatisée » de ce tableau.
